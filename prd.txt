**Versi:** 2.0

**Wilayah:** Kota Ternate
**Pemilik Produk:** Bappelitbangda
**Jenis Sistem:** Sistem Pendataan
**Dokumen:** Product Requirements Document

---

# 1. RINGKASAN PRODUK

Sistem Pendataan Kemiskinan Ekstrem & Stunting merupakan aplikasi web responsive yang digunakan untuk mengumpulkan,
menyimpan, memeriksa, memverifikasi, memvalidasi, mengolah, dan menyajikan data pendataan kemiskinan ekstrem dan
stunting di wilayah Kota Ternate.

Sistem berfungsi sebagai **basis data pendataan Bappelitbangda**.

Sistem tidak digunakan untuk pengelolaan program, intervensi, penganggaran, maupun penyaluran bantuan.

### Alur utama

```text
DATA LAPANGAN
↓
INPUT DATA
↓
VALIDASI OTOMATIS
↓
SUBMIT
↓
VERIFIKASI
↓
PERBAIKAN JIKA DIPERLUKAN
↓
VALIDASI
↓
DATA VALID
↓
DATABASE
↓
DASHBOARD
↓
LAPORAN
↓
BAHAN PERENCANAAN
```

# 3. PRINSIP PRODUK

Sistem harus mengikuti prinsip berikut:

### 3.1 Single Identity

Satu individu harus memiliki satu identitas utama berdasarkan NIK apabila NIK tersedia.

### 3.2 Data Terstruktur

Data harus disimpan berdasarkan entitas dan relasi yang jelas.

### 3.3 Role Based Access

Pengguna hanya dapat mengakses data dan fungsi sesuai role serta wilayah kewenangannya.

### 3.4 Traceability

Aktivitas penting pengguna harus dapat ditelusuri melalui audit log.

### 3.5 Validation First

Data harus melewati validasi otomatis sebelum dapat dikirim untuk proses verifikasi.

### 3.6 Historical Data

Data historis, khususnya pengukuran anak dan aktivitas verifikasi, tidak boleh ditimpa tanpa mekanisme pencatatan
perubahan.

### 3.7 Configurable Reference

Data referensi yang bersifat administratif harus dapat dikelola melalui Master Data.

### 3.8 Separation of Scope

Sistem hanya berfungsi sebagai sistem pendataan dan tidak menjadi sistem pengelolaan bantuan/intervensi.

# 9. KONSEP WILAYAH DAN SCOPE AKSES

Sistem menggunakan struktur:

```text
KOTA TERNATE
│
├── KECAMATAN
│ │
│ ├── KELURAHAN/DESA
│ │
```

```text

↓
```

### Aturan

* Super Admin → seluruh wilayah.
* Bappelitbangda → seluruh wilayah.
* Kecamatan → kecamatan dan wilayah bawahannya.
* Desa/Kelurahan → hanya wilayahnya.

* Viewer → sesuai scope yang diberikan.

User tidak boleh melihat data di luar scope wilayahnya kecuali memiliki permission khusus.

# 23. RELASI KELUARGA ↔ ANGGOTA ↔ ANAK/ORANG TUA

## 23.1 Struktur

```text
KELUARGA
│
├── 1 : N
│
▼
ANGGOTA KELUARGA
│
├── Ayah
├── Ibu
├── Anak
└── Anggota lainnya
```

Data anak pada modul stunting dapat terhubung dengan:

```text
KELUARGA
↓
ANGGOTA KELUARGA
↓
ANAK
```

## 23.2 Relasi Anak

Field yang direkomendasikan:

* `anggota_keluarga_id`;
* `ayah_anggota_id`;
* `ibu_anggota_id`.

Jika ayah/ibu sudah tersedia sebagai anggota keluarga, sistem harus menggunakan referensi tersebut daripada membuat
identitas baru.

## 23.3 Jika Orang Tua Belum Terdaftar

Sistem dapat menyimpan data orang tua sementara pada entitas `orang_tua`.

Jika kemudian identitas tersebut ditemukan dalam `anggota_keluarga`, sistem dapat menghubungkannya.

## 23.4 Aturan Identitas

NIK digunakan sebagai identifier utama individu apabila tersedia.

Sistem harus:

* memeriksa format NIK;
* mendeteksi NIK duplikat;
* memberikan peringatan;
* tidak menghapus otomatis record yang dianggap duplikat.

## 23.5 Relasi

```text
1 keluarga
↓
N anggota keluarga

1 anggota keluarga
↓
dapat menjadi 1 anak

1 anak
↓
dapat memiliki 1 ayah
↓
dapat memiliki 1 ibu

1 anak
↓
N pengukuran
```

# 33. VALIDASI OTOMATIS

## 33.1 Validasi Identitas

Sistem melakukan:

* validasi NIK 16 digit;
* validasi KK 16 digit;
* field wajib;
* format tanggal;
* format nomor telepon.

## 33.2 Validasi Konsistensi

Contoh:

* tanggal lahir tidak boleh lebih besar dari tanggal pendataan;
* tanggal pengukuran tidak boleh sebelum tanggal lahir;
* usia dihitung otomatis;
* jumlah anggota harus sesuai jumlah record anggota;
* total pendapatan sesuai sumber pendapatan;
* total pengeluaran sesuai rincian pengeluaran;
* tanggal kelahiran konsisten dengan tanggal lahir anak;
* jenis kelamin konsisten dengan data identitas.

## 33.3 Validasi Duplikasi

Sistem mendeteksi:

* NIK sama;
* KK sama;
* kombinasi identitas sama;
* anak yang sama;
* keluarga yang sama.

Sistem tidak boleh menghapus data otomatis hanya karena terindikasi duplikat.

        # 65. ACCEPTANCE CRITERIA — PENDATAAN

        ### AC-001

        **Given** petugas memiliki akses
        **When** petugas mengisi seluruh field wajib
        **Then** sistem dapat menyimpan data.

        ### AC-002

        **Given** terdapat field wajib kosong
        **When** petugas melakukan submit
        **Then** sistem menolak submit dan menampilkan field yang harus dilengkapi.

        ### AC-003

        **Given** data belum selesai
        **When** petugas memilih Simpan Draft
        **Then** data disimpan dengan status DRAFT.

        ---

        # 66. ACCEPTANCE CRITERIA — VERIFIKASI

        ### AC-004

        **Given** data telah dikirim
        **When** verifikator membuka data
        **Then** seluruh data dan dokumentasi dapat diperiksa.

        ### AC-005

        **Given** data benar
        **When** verifikator memilih VALID
        **Then** status berubah menjadi VALID dan aktivitas tercatat.

        ### AC-006

        **Given** terdapat kesalahan
        **When** verifikator memilih PERLU PERBAIKAN
        **Then** catatan wajib diberikan dan data dikembalikan kepada petugas.

        ---

        # 67. ACCEPTANCE CRITERIA — DUPLIKASI

        ### AC-007

        **Given** NIK telah digunakan
        **When** user memasukkan NIK yang sama
        **Then** sistem menampilkan peringatan potensi duplikasi.

        ### AC-008

        **Given** data terindikasi duplikat
        **When** verifikator menetapkan DUPLIKAT
        **Then** status berubah menjadi DUPLIKAT dan tercatat dalam audit log.

        ---

        # 68. ACCEPTANCE CRITERIA — PENGUKURAN

        ### AC-009

        **Given** anak telah memiliki tanggal lahir
        **When** petugas memasukkan tanggal pengukuran
        **Then** sistem menghitung usia saat pengukuran.

        ### AC-010

        **Given** anak telah memiliki pengukuran sebelumnya
        **When** pengukuran baru dimasukkan
        **Then** record lama tetap tersedia.

        ---

        # 69. ACCEPTANCE CRITERIA — DOKUMENTASI

        ### AC-011

        **Given** user mengunggah file
        **When** file memenuhi ketentuan
        **Then** sistem menyimpan file dan metadata.

        ### AC-012

        **Given** file tidak memenuhi ketentuan
        **When** user melakukan upload
        **Then** sistem menolak file dan memberikan alasan.

        ---

        # 70. ACCEPTANCE CRITERIA — LAPORAN

        ### AC-013

        **Given** terdapat data
        **When** user memilih filter wilayah/periode/status
        **Then** sistem menampilkan data sesuai filter.

        ### AC-014

        **Given** user memiliki permission export
        **When** user memilih Excel/CSV/PDF
        **Then** sistem menghasilkan file sesuai filter dan scope akses.

        ---

        # 71. ACCEPTANCE CRITERIA — AKSES

        ### AC-015

        **Given** user hanya memiliki akses Kecamatan A
        **When** user mencari data Kecamatan B
        **Then** data Kecamatan B tidak ditampilkan.

        ### AC-016

        **Given** user tidak memiliki permission edit
        **When** user membuka detail data
        **Then** tombol edit tidak tersedia atau tindakan ditolak.

            menentukan kebijakan pembangunan, tidak menentukan penerima bantuan, dan tidak menggantikan kewenangan
            instansi terkait. Fungsi utama sistem adalah menyediakan **data pendataan yang terstruktur, terdokumentasi,
            dapat diverifikasi, dapat ditelusuri, dan dapat digunakan sebagai bahan perencanaan pembangunan daerah.**
